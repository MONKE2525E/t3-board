# Protocol references

T3 Board independently implements the documented protocol facts below. No vendor executable, firmware, or SignalRGB plugin source is distributed with this project.

- [SignalRGB SONiX controller](https://gitlab.com/signalrgb/signal-plugins/-/blob/Development/Plugins/Sonix/SONIX_Keyboard_Controller_2.js), inspected at Development commit `2343f7f`. Reference for AK820 physical LED addresses and the FF13 feature-report frame sequence. This mapping is also present in the official Pro driver.
- [SignalRGB transport documentation](https://docs.signalrgb.com/developer/plugins/writes-and-reads/), distinguishes feature reports from output reports.
- [gohv AK820 Pro driver](https://github.com/gohv/EPOMAKER-Ajazz-AK820-Pro), reference for legacy global lighting mode packets and Linux report handling. Global blue and white changes were witnessed on the target device.
- [AK820 Pro Modder](https://github.com/wsclx/ak820pro-modder), MIT-licensed protocol research for the newer output-report variant. Its transport did not respond on the connected FF13 device, so it is not used by this application.
- [AJAZZ Control Center protocol research](https://github.com/Aiacos/ajazz-control-center/blob/main/docs/protocols/keyboard/ak980pro_perkey_rgb_protocol.md) and [F108 Pro protocol research](https://github.com/parsiya/f108-pro/blob/main/ai-docs/hid-protocol.md), references for related SONiX per-key variants. These describe other models and cannot establish AK820 Pro compatibility.
- [Official AK820 Pro driver download](https://epomaker.com/blogs/software/ajazz-ak820-pro-driver), ANSI version 1.0.0.5. Its layout confirms the same LED addresses. Inspection of its realtime lighting routine identifies the `04 20` header with byte 8 set to `08`, eight 64-byte RGB chunks, and the `04 02` apply command. Windows HID buffers prefix these payloads with report ID zero. The realtime routine sends no extra blank chunk or START/FINISH commands. Custom mode is `80`, selected through `04 13` with byte 8 set to `01`. A saved custom palette uses `04 23` with byte 8 set to `09`, 576 payload bytes, and an `AA 55` trailer. Mode and saved-palette transactions use START, APPLY, and FINISH. These facts are independently implemented. Physical testing confirmed custom mode, per-key colors, and continuous realtime animation. A lone realtime frame briefly changes the LEDs before the saved palette returns; steady colors require repeated updates too.

Runtime HID access uses `node-hid`. Build and verification use TypeScript, Vite, ESLint, typescript-eslint, and Prettier. Their licenses remain in their installed package directories.
